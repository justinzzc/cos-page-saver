# 多 COS 配置技术设计

## 数据模型与迁移

`chrome.storage.local` 新增 `profiles`、`defaultProfileId` 与 `lastUsedProfileId`。每个配置包含稳定 `id`、用户填写的 `name` 及现有 COS 字段。首次读取时，若不存在 `profiles` 且旧 `settings` 有有效字段，则生成一个名为“默认 COS”的配置并写回新结构；保留旧 `settings` 仅为升级兼容，不再作为正常写入来源。

`storage.js` 作为唯一的数据模型入口，负责读取、迁移、校验、创建、更新、删除和默认配置选择。Popup、配置页和后台均通过该模块读取配置，避免重复解析存储结构。

## 配置页

配置页显示配置列表和当前编辑表单。可新建配置、选择配置、保存修改、删除非唯一配置及设为默认。每次保存、删除或默认变更后，调用后台消息同步右键菜单。

## 右键菜单与上传

后台在安装、启动和 `REFRESH_CONTEXT_MENU` 消息后重建菜单：创建“云剪存”父项；第一项为默认配置，标题为“默认：<名称>”；第二项为上一次成功剪存配置，标题为“上一次：<名称>”。若两者相同则仅显示默认项，其他配置随后列出。每个子项 ID 携带 profile ID。点击时按 ID 读取对应配置并将其传入 `savePage(tabId, settings)`；成功上传后更新 `lastUsedProfileId` 并刷新菜单。

Popup 从存储读取默认配置，展示其名称和 Bucket，保存时在消息中传入默认配置 ID。后台仍以存储为准取得配置并校验，避免由页面消息携带密钥。

## 兼容与失败行为

无配置或默认配置失效时，Popup 禁用保存按钮；右键父菜单下显示“请先配置 COS”，点击后打开配置页。删除默认配置时自动将剩余第一项设为默认；删除最后一项后清除默认项。菜单中配置名称做显示截断，完整名称仍保存在存储。

## 风险与回滚

主要风险是迁移丢失旧配置，迁移仅在新结构为空且旧设置存在时执行，并保留旧键。回滚时旧版本仍可读取旧 `settings`；新版本创建的额外配置不会被旧版本使用。
